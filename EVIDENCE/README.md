# 📁 Evidence Directory

Этот каталог содержит артефакты и доказательства для различных процессов обеспечения безопасности и соответствия.

## Структура
```
EVIDENCE/
├── 📄 README.md # This file
├── 🏗️ ARCHITECTURE.md # Evidence system architecture
├── 📘 DS_GUIDE.md # Guide for DS report section
├── 🌐 index.html # Web view of evidence
├── 📁 P09/ # Practice 09: SBOM & SCA
│ ├── 📄 README.md # Practice-specific docs
│ ├── 🔗 sbom.json -> sbom-latest.json
│ ├── 📊 sbom-latest.json # Latest SBOM
│ ├── 📊 sbom-{commit}.json # Historical SBOMs
│ ├── 🔗 sca_report.json -> sca-latest.json
│ ├── 📊 sca-latest.json # Latest SCA report
│ ├── 📊 sca_report-{commit}.json # Historical SCA
│ ├── 🔗 sca_summary.md -> sca-summary-latest.md
│ ├── 📝 sca-summary-latest.md # Latest summary
│ ├── 📝 sca_summary-{commit}.md # Historical summaries
│ ├── 📋 evidence-manifest.json # Traceability manifest
│ └── .gitkeep # Preserve directory
└── 📁 templates/ # Report templates
├── 📝 ds-report-template.md # DS section template
└── 📊 evidence-summary.json # JSON summary structure
```




## Назначение

Каждая поддиректория (PXX) соответствует конкретному требованию или практике:
- **P09**: Генерация и хранение SBOM (Software Bill of Materials)
- Другие директории добавляются по мере необходимости


## 🚀 How to Use Evidence

### For Developers
1. **Check PR Comments** - Automatic evidence links in every PR
2. **Review SCA Findings** - Check `sca_summary.md` for vulnerabilities
3. **Verify SBOM** - Review `sbom.json` for component inventory

### For Auditors
1. **Traceability** - Follow links in `evidence-manifest.json`
2. **Historical View** - Compare artifacts across commits
3. **Compliance** - Verify automated collection process

### For DS Report Creation
See [DS_GUIDE.md](DS_GUIDE.md) for detailed instructions on incorporating evidence into the final report.

## 🔗 Traceability Model
```
Commit → Workflow Run → Artifacts → Evidence Manifest → DS Report
↓ ↓ ↓ ↓ ↓
GitHub Actions EVIDENCE/ JSON Metadata Final Output
```

Each artifact is traceable back to:
- Specific commit SHA
- GitHub Actions workflow run
- Generation timestamp
- Tool versions used

## 📈 Artifact Lifecycle

1. **Generation** - Automated on push/PR via GitHub Actions
2. **Storage** - Stored in `EVIDENCE/P09/` with commit-specific copies
3. **Symlinks** - `{artifact}.{ext}` always points to latest version
4. **Retention** - 90 days in artifacts, indefinite in repository
5. **Cleanup** - Old versions can be archived via git history

## ⚠️ Conflicts with Other Practices

### Non-conflicting Design
The `EVIDENCE/` structure is designed to coexist with other practices:

1. **Directory-based isolation** - Each practice (P09, P10, etc.) has its own subdirectory
2. **Clear naming** - No overlap with `docs/`, `tests/`, or `src/`
3. **Git-friendly** - Symlinks and patterns work with standard git
4. **Tool-agnostic** - Can be generated by any CI/CD system
