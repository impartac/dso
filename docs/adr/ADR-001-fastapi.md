# ADR 001: Выбор FastAPI как основного веб-фреймворка
## **Status : Accepted**

## **Context:**
Требуется реализовать Media Catalog API с строгими security NFR:
* **NFR-2**: Лимиты запросов
* **NFR-3**: Маскирование ошибок
* **NFR-5**: Валидация JWT
* **NFR-6**: Приватность данных
* **NFR-7**: Управление сессиями

## **Рассматривались альтернативы:**
* **Django REST Framework** - избыточен тяжеловесная ORM
* **Flask** - требует много boilerplate кода для валидации
* **Node.js/Express** - слабая типизация, сложнее обеспечить NFR-3

## **Solution:**
Использовать FastAPI как основной веб-фреймворк.

## **Обоснование:**

* Встроенная валидация через Pydantic - автоматически обеспечивает NFR-3 (маскирование ошибок) через стандартизированные error responses
* Dependency Injection system - идеально для реализации NFR-5 (JWT валидация) как зависимостей
* Background Tasks - позволяет отделить логику аудита (NFR-1, NFR-2) от основного response
* Middleware поддержка - для глобальной реализации NFR-6 (маскирование в логах)
* Автодокументация OpenAPI - прозрачность API контрактов

## **Consequences:**

✅ Легко реализовать rate limiting через dependencies (@limiter)

✅ Встроенная сериализация Pydantic скрывает технические детали (NFR-3)

✅ Возможность кастомизации exception handlers для унифицированных ошибок

⚠️ Требует Python 3.7+

⚠️ Меньше готовых решений по сравнению с Django
