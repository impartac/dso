## Feature: Защита от брутфорса аутентификации

  ### Scenario: Блокировка IP при multiple failed logins
    Given IP 192.168.1.100 с 5 неуспешными логинами за 5 минуты
    When происходит 6-я неуспешная попытка логина
    Then возвращается HTTP 429
    And в теле сообщение "Слишком много запросов"
    And в аудит-лог пишется событие "auth_ip_blocked"
    And последующие запросы с этого IP блокируются 15 минут

  ### Scenario: Успешный логин после блокировки по таймауту
    Given IP был заблокирован 16 минут назад
    When происходит попытка логина
    Then запрос обрабатывается нормально

## Feature: Лимит создания медиа-контента

  ### Scenario: Срабатывание лимита на создание медиа
    Given пользователь создал 10 медиа за 50 секунд
    When он делает 11-й запрос POST /media
    Then возвращается HTTP 429
    And заголовок Retry-After: 60
    And в лог пишется rate_limit_triggered

  ### Scenario: Сброс лимита после минуты
    Given пользователь достиг лимита 1 минуту назад
    When он делает запрос POST /media
    Then запрос обрабатывается успешно

## Feature: Защита от SQL инъекций
  ### Scenario: Попытка SQL инъекции в поисковом запросе
    Given пользователь с валидным токеном
    When отправляет запрос GET /media?search=' OR '1'='1'--
    Then система возвращает HTTP 400
    And в логах появляется событие "sql_injection_attempt"
    And результат поиска пуст

## Feature: Валидация JWT токенов
  ### Scenario: Использование просроченного токена
    Given пользователь с просроченным JWT токеном
    When отправляет запрос к защищенному endpoint
    Then система возвращает HTTP 401
    And в логах фиксируется "jwt_expired"
    And токен добавляется в blacklist

## Feature: Устойчивость к DoS атакам
  ### Scenario: Атака на endpoint поиска медиа
    Given botnet отправляет 1000 RPS на GET /media/search
    When система обнаруживает аномальную нагрузку
    Then активируется rate limiting
    And трафик фильтруется через WAF
    And легитимные пользователи продолжают получать service
    And система автоматически масштабируется

## Feature: Безопасное управление сессиями
  ### Scenario: Истечение таймаута сессии
    Given пользователь аутентифицирован
    When пользователь неактивен 61 минуту
    Then сессия автоматически инвалидируется
    And пользователь перенаправляется на login page
    And требуется re-authentication для следующих запросов
